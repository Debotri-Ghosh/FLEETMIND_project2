# Decision Intelligence — replacing the hand-tuned risk heuristic

**Status:** Phase 0 executing. Phases 1–5 planned, not started.
**Branch:** `improve/decision-intelligence`
**Authored:** 2026-10-07 (folder dated 2026-10-06 per the originating brief)

---

## 1. Why this exists

FleetMind's maintenance decisions are currently made by four deterministic rule
functions in `backend/fleetmind/agents/agents.py`. Those functions are honest,
auditable and fast, and they were the right thing to build first. They are also
built almost entirely out of invented constants, and one of them discards the
only quantity in the system that was actually learned from data.

Every number below was read out of the source, and the behavioural claim was
measured by running the real functions:

| Constant | Value | Where it came from |
|---|---|---|
| `FAULT_SEVERITY` | Normal 0.0, Ball 0.4, InnerRace 0.7, OuterRace 0.85 | Invented. No citation, no fit, no measurement. |
| `LOAD_RISK_FACTOR` | 0.80 / 1.00 / 1.15 / 1.30 per HP | Invented. Direction is physically sensible; the magnitudes are not derived from anything. |
| Risk blend | `risk = severity × load × (0.7 + 0.3 × conf)` | Invented. The 0.7/0.3 split has no justification. |
| Urgency bands | 0.15 / 0.40 / 0.70 | Invented. Nothing ties a threshold to a consequence. |
| Diagnostic confidence | `min(0.95, 0.5 + rms × 3.0)` | Invented, and it **overwrites** the model's probability. |

### The measured flaw

`diagnostic_agent()` computes a `diagnosis_confidence` from signal RMS and
stores it under that name. `risk_agent()` then reads `diagnosis_confidence` —
not the model's `confidence`. The classifier's predicted probability therefore
never reaches the risk score at all; only the class *label* does.

Run against the real functions (`predicted_label="OuterRace"`, `load_hp=3`,
fixed signal):

```
model confidence = 0.26    -> risk_score = 1.0   urgency = critical
model confidence = 0.55    -> risk_score = 1.0   urgency = critical
model confidence = 0.9991  -> risk_score = 1.0   urgency = critical
```

A barely-above-chance prediction and a near-certain one produce byte-identical
decisions. Meanwhile the thing that *does* move the score is signal amplitude:

```
rms = 0.01 -> diagnosis_confidence = 0.265  risk = 0.8613
rms = 0.10 -> diagnosis_confidence = 0.800  risk = 1.0000
rms = 0.40 -> diagnosis_confidence = 0.950  risk = 1.0000
```

This is the single most attackable thing in the project. A reviewer who asks
"what happens when the model is unsure?" currently gets the answer "nothing
changes", and that is indefensible for a system whose stated purpose is to
decide when a human should act.

### What "better" means here

Not "more layers" and not "an LLM decides". Better means **every number in the
decision is either measured from held-out data or is an explicit, auditable
domain input stated in real units** — and the decision carries a stated
statistical guarantee. Four standard, citable techniques get us there:

1. **Probability calibration** (temperature scaling) — make the model's
   confidence mean what it says, measured by Expected Calibration Error and
   Brier score on held-out recordings.
2. **Conformal prediction** — emit a prediction *set* with a guaranteed
   marginal coverage level instead of an overconfident point prediction. At
   62–72% accuracy, a point prediction is overconfident by construction.
3. **Expected-cost decision policy** — replace invented thresholds with an
   explicit cost matrix in engineering units (cost of an unplanned bearing
   failure vs. cost of an unnecessary inspection) and choose the action that
   minimises expected cost under the calibrated posterior.
4. **Sequential evidence accumulation** (SPRT / CUSUM) — decide over a run of
   consecutive windows with a controllable false-alarm rate, instead of letting
   one 0.17-second window flip a machine into maintenance.

Each of these replaces a guess with either a measurement or a stated
assumption. That is the whole argument.

### What happens to the rule-based agents

They are **retained, renamed as the baseline, and no longer presented as the
system's intelligence.** Deleting them would be a worse thesis, not a better
one: a negative control is evidence. Every claim the new layer makes will be
stated as "calibrated decision layer vs. heuristic baseline, measured on
held-out recordings". They also stay in place because:

- `agents/run.py`'s documented batch figures must remain reproducible;
- the Evidence Package recomputes RMS/peak via `diagnostic_agent()`;
- 4,367 stored decisions were generated by them.

They stop being the authoritative path. They do not stop existing.

## 2. Non-negotiables carried in from `CLAUDE.md`

- Splits are **by recording / experiment id**, never by individual window
  (`augmentation/exp_split.py:stratified_experiment_split`). Calibration and
  conformal both need held-out data, and a per-window split would leak.
- Model input is always `ml/model.py:to_fft_magnitude()` on `raw_values`.
- Bearing characteristic frequencies remain **independent corroboration**, not
  a model explanation.
- The LLM layer may not originate a number. The decision layer becomes the new
  authoritative source those tools read from.
- Any new endpoint is closed by default.
- Risk must key off `load_hp`, never `depot_id`.
- **Every test that asserts "nothing is wrong" must also assert that it
  examined something**, with a positive count.

## 4. Phases

### Phase 0 — Measure the baseline. Build no new intelligence. ← *this phase*

An improvement cannot be claimed without a before-number, and none of the
project's existing figures are decision-quality figures. Phase 0 produces them.

1. **`decision/holdout.py`** — one canonical held-out split per site, grouped by
   recording, reusing `stratified_experiment_split`. Exposed as a function so
   every later phase scores against the identical partition.
2. **`decision/probs.py`** — load a trained per-site checkpoint, run
   `to_fft_magnitude()` → softmax, and return full 4-class posteriors for every
   held-out window. No database required; reads the archive.
3. **`decision/calibration.py`** — ECE (equal-width bins), Brier score,
   per-bin reliability table, mean confidence vs. accuracy gap. Measurement
   only; no temperature fitting yet.
4. **`decision/quality.py` + `decision/baseline.py`** — score the *existing*
   heuristic on held-out recordings: false-alarm rate (a Normal recording that
   produces a high/critical decision), miss rate (a faulted recording that
   never does), and time-to-detection in windows.
5. **A test that pins the measured flaw** — asserts that the current risk score
   is invariant to the model's confidence, so the regression cannot be
   reintroduced silently once Phase 1 fixes it. The test names the three
   confidence values it tried.
6. **A CLI** (`python -m fleetmind.decision.report`) writing
   `mlruns/decision/phase0/{site}.json` plus a printed summary.

**Phase 0 exit criteria:** real ECE/Brier/reliability numbers per site and real
false-alarm/miss/time-to-detect numbers for the heuristic, all on held-out
recordings, all reproducible from one command. No behaviour change anywhere in
the running application.

### Phase 1 — Calibration
Fit a single temperature per site on a calibration split (held-out from both
train and test), re-measure ECE/Brier, publish before/after. Temperature is
**fitted, not chosen**. Ship only if ECE improves; report honestly if it does
not.

### Phase 2 — Conformal prediction sets
Split-conformal on calibrated softmax scores, target 90% marginal coverage.
Report empirical coverage and mean set size on held-out recordings. A set of
size 1 is an actionable diagnosis; size 3 is an honest "we don't know", and the
UI must be able to say so.

### Phase 3 — Expected-cost policy
`costs.py` states a cost matrix in engineering units with a comment naming every
assumption. `policy.py` chooses among {monitor, inspect, schedule maintenance,
stop machine} by minimising expected cost under the calibrated posterior.
Re-measure false-alarm and miss rates against the Phase 0 baseline. The cost
matrix is configurable, and the report shows how the decision boundary moves
with it — sensitivity, not a single magic setting.

### Phase 4 — Sequential evidence accumulation
SPRT over consecutive windows per recording with stated α/β. Report
time-to-detection and false-alarm rate against Phase 0 and Phase 3. This
supersedes the k-of-m persistence heuristic drafted on `improve/rigor`, which
had no error guarantee.

### Phase 5 — Wire it in
`pipeline.py` calls the new policy; `agents/tools.py` gains tools exposing the
calibrated posterior, the conformal set and the expected-cost table so the LLM
can still only quote; the API surfaces the decision alongside the baseline's;
the UI shows the prediction set and the chosen action's expected costs. Docs
(`README`, implementation report, walkthrough, `DEMO_SCRIPT`) updated with the
measured before/after.

## 5. Risks

| Risk | Handling |
|---|---|
| Calibration may not improve ECE on 62–72%-accurate models | Report it either way. A negative calibration result is still a result, and this project already publishes a negative federated result. |
| Only 64 recordings total; held-out folds are small | State the fold sizes beside every figure. Grouped k-fold across seeds for the headline numbers. |
| **Each site has a single Normal recording** | Stated as a hard limitation: Normal cannot appear in a held-out fold under a grouped split, so false-alarm rate on Normal recordings is measurable only across sites or by leaving a site out. This must appear in the output, not in a footnote. |
| Cost matrix is still a human input | Yes — but an explicit, unit-bearing, sensitivity-analysed one, which is categorically different from `0.85`. Say so plainly. |
| Changing the policy changes which machines are flagged | Exactly as in Slice G. The change is explicit, the before/after is published, and the baseline remains runnable. |
